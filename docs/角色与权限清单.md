# 角色与权限清单

依据：`shared/roles.ts`（角色定义与范围判定）、`client/src/components/DashboardLayout.tsx`（菜单可见性）、`server/routers.ts`（接口守卫），以及 `scripts/import-users.ts` 的角色映射。前端菜单只控制"看到什么"，**最终权限以服务端校验为准**；本文档与代码实现保持一致。

更新日期：2026-10-03

## 二、各角色权限明细

### 1. 研究生院主管（graduate_admin，全校）

- 菜单：工作台、全校课程、**听课计划、全部评价、评价进度、统计仪表盘、用户管理、上传课程数据**
- 课程：查询全校所有学期课程，无学院限制
- 评价：可代替督导创建/修改听课评价（`supervisorProcedure` 放行，菜单同步呈现听课计划入口）；可查看全校所有人的评价详情、评语
- 导出：全校评价 Excel / PDF / 单条导出、打印
- 统计：全校三图、学院明细、分学期查看
- 管理：用户列表、调整角色/附加角色/学院/督导范围；新建学期、修改学期、设置当前学期；上传两类课表
- 听课计划：可使用（创建/修改本人计划），可查看他人计划需组长及以上

### 2. 督导专家——校级（supervisor_expert + scope=school）

- 菜单：工作台、全校课程、**听课计划、评价记录**
- 课程：浏览全校课程，可筛选学院/校区/周次
- 评价：只能评价**当前时间及以后**的课程；同一课程已被他人评价后不可再评（独占）；可保存草稿、自动保存、继续编辑
- 查看：默认只看**本人**评价记录与详情；不能看他人评语
- 导出：本人记录可导出；无管理入口（用户管理/统计仪表盘/上传课程数据不可见，接口层同样拒绝）

### 3. 督导专家——院级（supervisor_expert + scope=college）

- 同校级督导的全部能力，但课程与评价范围**限定在所属学院**（按 `college` 字段，可含多个学院，顿号分隔）
- 学院字段缺失/为空时：查询与写入一律拒绝并提示"联系管理员补充所属学院"（2026-10-02 修复的安全默认，不会退化为全校）
- 查看：默认只看本人评价；**不能**查看本院整体统计图表（如需放开为"只看聚合数字、不看任何人明细"，待研究生院确认后一行配置即可）

### 4. 学院教学秘书（college_secretary，限本学院）

- 菜单：工作台、全校课程、**督导评价、评价进度、统计仪表盘**
- 课程：只能查询本学院课程（多学院账号为多个学院并集；括号官方全称如"法学院（知识产权学院）"已自动解析到课表简称，2026-10-04 修复）
- 评价：**不能提交评价**（接口 `supervisorProcedure` 拒绝）；只读查看本学院全部评价详情、评语
- 进度：本学院课程评价进度板块（已评价/全部课程，可点开明细）
- 统计：**学院统计仪表盘（全院口径）**——本院课程总数、已提交评价、覆盖率、平均评分及本院明细行，按 2026-10-04 研究生院权限表收敛（此前短暂开放过全校聚合口径）；不含其他学院数据，也无全校用户管理、课表上传
- 导出：本学院评价 Excel / PDF

### 5. 学院分管领导（双身份：督导专家（院级）+ 学院管理）

- 侧边栏 = 两种身份的**能力并集**：工作台、全校课程、听课计划、督导评价、评价进度、统计仪表盘——**切换身份不隐藏任何已授权入口**（2026-10-03 修复：此前切到秘书视图会丢失评价入口）
- 切换身份改变的是**工作台视图**：
  - **督导专家（院级）**视图：待听课计划/已完成评价，本院课程可评，本人评价可查
  - **学院管理**视图（底层为教学秘书的本院只读能力）：本学院已督导课程等只读面板，本院全部评价可查、可导出打印；统计仪表盘为**全院口径**
- 切换入口：左下角用户卡片 → "切换身份"；切换仅改变视图，服务端始终按完整角色集合（主角色+附加角色）校验
- 身份选择**按账号 + 浏览器标签页分别保存**（2026-10-03 确认）：换账号登录不继承上一个账号的身份，新开标签页从主角色开始，多标签页互不影响
- 数据范围始终限定本院

### 6. 督导组长（supervisor_leader，全校）※通讯录当前未分配，系统保留

- 菜单同校级督导；额外可查看**全部评价**（含他人评语）、可导出
- 可修改范围内**他人评价**（`evaluations.update` 放行组长）；**不能**仅凭组长身份修改或删除他人听课计划——计划仅限本人操作，研究生院主管/系统管理员可清理（`canMutateListeningPlan`）

### 7. 系统管理员（admin，全校）※技术角色，不发给业务人员

- 菜单：督导菜单 + 全套管理菜单（回归测试保障两个分支都生效）
- 拥有研究生院主管的全部管理能力；与业务主管分开描述，避免"技术管理员可读所有评语"被默认化

### 8. 普通用户（user）

- 兜底默认角色：可登录、可**浏览全校课程**（只读，`courses.list` 对所有登录用户开放）及查看通知；**不能**创建听课计划或评价（`supervisorProcedure` 拒绝）；无管理入口

## 三、通用规则（对所有角色生效）

1. **登录**：工号 + 密码；初始密码为工号，登录后可自行修改（旧密码校验）。
2. **学期范围**：所有查询、统计、导出统一按顶部"查看学期"所选学期；历史学期只读，写入接口拒绝；切换查看学期不影响全校当前学期。
3. **评价独占**：一门课程已有已提交评价后，其他督导不能再评。
4. **时间限制**：只能对当前时间及以后的课次创建评价；过去日期的听课计划前端禁止选择。
5. **数据保护**：删除按钮均有确认；课程归档不物理删除；有评价/计划关联的课程导入时不更新不删除。
6. **越权防护**：督导不能凭评价 ID 查看他人评语；院级角色不能访问未授权学院；直连接口、导出、打印与页面同权校验。
7. **角色变更安全校验**（2026-10-03 功能升级，`shared/userAdmin.ts`）：用户管理的四个变更接口在写库前统一校验——受限岗位（学院秘书/院级督导）必须有所属学院，否则拒绝；管理员不能移除自己的管理权限；系统至少保留一名管理员，不能降级最后一个管理账号。绕过页面直连接口同样被拦截。
8. **授权变更留痕**（2026-10-03 功能升级，`user_admin_logs` 表）：主角色、附加角色、所属学院、督导范围的每次修改都记录操作人、对象、前后值和时间；用户管理页"最近授权变更"面板展示最近 50 条。
