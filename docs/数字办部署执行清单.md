# 数字办虚拟机部署执行清单

用途：数字办服务器资源审批通过、对接群建立后，由开发方**远程执行**的部署清单（上线前会议决议："部署过程由开发方远程操作完成"）。执行时逐项勾选并记录证据，完整迁移背景见备份包内 `RESTORE.md` 与《迁移上线说明_新云服务器.md》。

## 零、执行前需向数字办索取（缺一即暂停）

- [ ] 虚拟机 SSH 地址、账号、密码或密钥（确认操作系统版本，目标 Ubuntu 22.04）
- [ ] 资源配置确认（申请：4 核 8G / 1T 硬盘；至少确认硬盘与内存）
- [ ] 内网/外网访问策略：哪些端口对外开放（Web 80/443；SSH 仅管理网段）
- [ ] 域名与 DNS：数字办分配的域名或自行拟定报备的域名；证书签发方式（校内证书 or Let's Encrypt）
- [ ] 备份策略与存放位置（数据库每日备份 + 保留周期）

## 一、装底座（约 1 小时）

- [ ] Node 22 LTS（或与当前构建一致的 22.x）、MySQL 8.0、Nginx、PM2（`npm i -g pm2`）
- [ ] 时区设为 Asia/Shanghai；创建部署账号与目录 `/root/zjgsu-supervisor`（与原服务器结构一致，便于脚本复用）
- [ ] 防火墙：仅放行 80/443 与管理 SSH

## 二、拉代码与配置（约 30 分钟）

- [ ] `git clone https://github.com/1739467001-svg/zjgsu-supervisor-v4-glm.git`（或内网 git 镜像），记录完整 SHA：____________（v4.0.0 定版提交）
- [ ] `pnpm install --frozen-lockfile`
- [ ] 编写 `.env`（**不入库**）：`DATABASE_URL`（新库）、`JWT_SECRET`（新生成 32 字节随机值——**旧密钥已知外泄，严禁复用**）、`PORT=3000`
- [ ] `pnpm db:push` 或按迁移日志建库建表（迁移 0010 及之前全部应用）

## 三、数据导入（约 1 小时，顺序固定）

- [ ] 恢复历史数据：`gzcat db_zjgsu_supervisor.sql.gz | mysql -u… zjgsu_supervisor`（来源：阿里云备份包 `10_db/mysql/`，行数核对 `SELECT COUNT(*)`：users 58→导入通讯录后 101+1、courses 2269、course_evaluations 81、listening_plans 57）
- [ ] 应用学期归档迁移 0006-0010 → 验证：81 条评价 + 57 条计划全部归档至 2025-2026-2
- [ ] 导入新学期课表（当前学期 2026-2027-1，起始日 **2026-09-14**，18 周）：
      `npx tsx scripts/import-courses.ts <总课表.xls> <MBA课表.xls> --semester "2026-2027/第一学期" --start-date 2026-09-14 --weeks 18 --apply --activate`
      验收基准：**1832 门 / 24 学院 / MBA学院 354 / 工商管理学院 88**
- [ ] 导入用户：`npx tsx scripts/import-users.ts <浙工商督导系统通讯录0630.xlsx> --apply`（101 行 → 100 人，双身份 26）
- [ ] 核对：`npx tsx scripts/permission-selfcheck.ts` 与 `npx tsx scripts/verify-semester-archive.ts` 全部 PASS

## 四、构建与启动（约 30 分钟）

- [ ] `pnpm build`（避免在小内存机器上跑类型检查与全量测试——本地已完成，见测试报告）
- [ ] PM2 启动（`ecosystem.config.cjs`）→ `pm2 save && pm2 startup`
- [ ] Nginx 反代 + 证书 → `nginx -t && nginx -s reload`
- [ ] 数据库每日备份 cron：复用 `scripts/server-backup.sh`（**部署后在 Linux 上补跑其平台相关测试**）

## 五、验收（按《生产发布准备清单》第四关，逐项留证）

- [ ] 五角色 + 双身份真实账号抽验（登录/菜单/范围/统计口径：主管全校、秘书本院、院级督导无统计）
- [ ] 学期切换：历史只读、新学期零评价；三图学院集合与明细对账
- [ ] 课表上传双入口：预览不写库、确认导入、错误模板拒绝
- [ ] 手机号等敏感信息前端无明文；导出 Excel/打印无敏感字段
- [ ] 记录：旧版 SHA → 新版 SHA（v4.0.0，以部署时 main HEAD 完整 SHA 为准，当前定版序列见 CHANGELOG）、构建产物 SHA256、备份标识、验收结论（通过/失败/未验证）

## 六、回滚预案

- 任一关键验收失败：PM2 停新进程，按备份标识恢复旧库与旧构建产物，DNS 不切换即无影响
- 切换后如需回退：先核对切换窗口内的新写入数据，禁止直接用旧库覆盖
