## 三、新发现问题与处置

**F-1｜X-Forwarded-For 可伪造（安全，已修复）**
新增登录限流后复查代理链路发现：nginx 用 `$proxy_add_x_forwarded_for`（追加模式）会把客户端自带的伪造 XFF 首段传给应用，攻击者可伪造 IP 绕过 IP 维度限流、也可污染他人 IP 造成误锁。修复：督导系统入口改为 `proxy_set_header X-Forwarded-For $remote_addr;`（单层代理直接取真实来源）。drcopilot 入口同款问题不属本系统，未动，建议其负责人跟进。

**F-2｜10-16 课表增量在服务器重置中丢失，且源文件未留存（需用户材料）**
GUI 中发现「工商管理学院 88 门」与 10-19 记录（121 门/全校 2172）不一致，追查定性：
- 10-20 重建恢复的是 **10-11 数据基线**（10-05 首次导入状态）——经双入口预览验证：总课表 1498 行 → 1478 门**全部匹配 0 漂移**，MBA 817 场次 → 354 门全匹配，第 0 周口径告警正确。当前库与手头 09-06 版课表文件**完全一致**，重建本身无差错。
- 10-16 出现的 2172 门（含工商管理学院 121 门）是用**一版更新的课表文件**（含补退选周新增的约 340 门课）导入的结果；该文件只在那次上传时用过，未存入项目目录，随服务器重置一起丢失。
- 影响：当前学期课表少了补选周新增的课（约 340 门），若老师 10-16~10-20 期间按新课表建过听课计划，对应课程现在会查不到。
- 处置建议：请向研究生院/教务索取**最新版排课信息表**（10 月中旬以后的导出版），由主管在「导入课表 → 总课表入口」重新上传即可（预览会显示新增/更新/删除明细，确认才写库；本次已实测 4.0.5 的预览链路工作正常）。

**F-3｜旧哈希资源请求返回 index.html（观察项，不处理）**
部署新版本后请求旧 hash 的 JS 返回 200 + index.html（SPA 兜底）。哈希命名的资源浏览器不会跨版本请求，且 MIME 为 text/html 不会被执行，无实际影响；如追求严格可在应用层对该路径返回 404。
