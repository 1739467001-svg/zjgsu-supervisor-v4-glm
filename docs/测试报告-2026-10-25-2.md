## 三、缺陷与处置

**B-1｜create 返回行可能串行（正确性，已修复 + 集成用例守护）**
`server/db.ts` 的 `createEvaluation` 与 `createListeningPlan` 在 INSERT 后按 `createdAt DESC LIMIT 1` 取回"刚建的行"。`createdAt` 为秒级精度，同一督导同秒内连建两条（同一门课补不同周次的听课计划是真实操作路径）时排序打平，返回另一条的行。影响：前端建草稿后按返回 id 跳转会打开错误的记录；提交通知的 `evaluationId` 也会挂错。修复：取 INSERT 的自增 `insertId` 按主键回读；兜底路径改按 `id` 倒序（单调不打平）。新增 2 条对真实 MySQL 的集成用例（旧实现下必失败）。

**B-2｜草稿转提交漏发通知（功能，已修复）**
提交通知（研究生院主管 + 本学院秘书）此前只在 `evaluations.create` 直接提交时发送；「草稿自动保存 → update 提交」路径不发。草稿自动保存（30 秒）是常态流程，绝大多数真实提交不走 create 路径。修复：抽出 `notifyEvaluationSubmitted` 共用函数，两条路径统一发送。

**P-1｜部署脚本残留行导致目录错位（运维过程，已即时恢复）**
v4.0.6 部署命令中残留一行实验性交换语句，`app-dist` 被挪走后容器找不到 /app 内容进入重启循环（约 3 分钟，04:57~05:00）。恢复后全量验证 healthy。教训已吸收：后续部署一律使用固化的脚本而非临时内联命令。
