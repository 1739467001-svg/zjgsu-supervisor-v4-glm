**缺陷与处置（均已修复并部署 v4.1.1）**

**F-1｜接口把明文口令带回客户端（安全，P1）**
auth.me、登录响应、users.list（账号管理列表）三处都按整行展开返回 `password` 字段；口令在库内即明文（默认=工号），主管经账号列表可读全校 101 个账号的口令原文。前端只需 `isDefaultPassword` 布尔标记，口令原文没有任何用途。修复：三处一律剥离 password（`const { password: _p, ...safe } = user`），isDefaultPassword 标记保留，前端无感。

**F-2｜预览面板「其他学院原样保留」恒为全学期总数（外观，P2）+ 失实文案**
旧算法 `existing - deleted - keptReferenced` 漏减 matchedIds，两个入口都显示 1832（应为另一入口的 354/1478）。同句「导入前已自动备份」为失实描述——系统只有每日 03:00 定时备份，并无导入动作触发的自动备份（对主管构成虚假安全承诺，本轮用户恰因数据安全关切要求先备份，故一并纠正）。修复：口径改 `existing - matched - deleted - keptReferenced`；移除失实文案。

**F-3｜非 .xls 文件直传接口返回 500 HTML（健壮性，P3）**
multer 文件过滤错误未被接住，落进 Express 默认错误页（500 + Internal Server Error），API 调用方拿不到可读信息。UI 本有前端扩展名拦截，真实用户不可达，属纵深防御补齐。修复：upload 路由尾部加 router 级错误中间件，统一 400 JSON（线上复验「只支持 .xls 或 .xlsx 格式的文件」）。

**过程事故（非产品缺陷）**

**首版发布漏设 VITE_BASE_PATH（07:13~07:15，约 3 分钟）**：本地打包未带子路径变量，客户端资源引用 /assets/… 绕过 /zjgsu-supervisor/ 路由全部 404，页面 HTML 200 但白屏。GUI 复测第一时间发现，带变量重建重发即修复；期间无用户登录。根因是构建命令约定未落文档（历次构建均人工带变量）——已在服务器 DEPLOY.md 补记正确命令，测试浏览器控制台同时观察到既有的 `%VITE_ANALYTICS_ENDPOINT%` 占位符未替换（umami 统计端点 400，v4.0.x 子路径部署以来即存在，纯环境噪音，不影响功能，记录备查）。
