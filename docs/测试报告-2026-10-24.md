## 二、测试侧修正（3 处，均为测试代码，未动产品代码）

三处失败经排查全部是**断言过时或平台可移植性问题**，产品行为经人工核库确认为设计正确：

1. **`scripts/server-backup.test.ts`（SIGPIPE 守护测试）**：该测试通过复现旧写法的 SIGPIPE 崩溃来守护回归，依赖 GNU tar 行为；macOS 的 bsdtar 在读端提前关闭时优雅退出 0，复现不出误报，故在 macOS 上必然失败。已限定该行为复现项仅在 Linux（备份脚本实际运行环境）执行；源码静态扫描项仍在所有平台守护同一坑位。
2. **`scripts/api-smoke.mjs`（导入确认断言）**：断言仍假设"确认导入 = 纯插入 +1"，未跟上 v3.0.0 起的「UPSERT + 按入口学院范围清理 + 引用保护」语义。实测导入课程正常入库（ semesterId=1 ），无引用的种子课「中级微观B」被按设计清理，有评价引用的「计量经济学A」被保护保留。已改为按预览 inserted/deleted 差量核算，并补两条断言（新课在库、被引用课程保留）。复跑 55/55。
3. **`server/courseImport.test.ts`（MBA 真实课表周次断言）**：断言仍是"周次 ≥1"的旧语义；v4.0.3 起开学前场次合法记第 0 周。真实 MBA 课表含 2026-09-12/13（开学前周六日）共 45 门课程记为周 0，解析器已出「人工核对」警告。已更新为 0~18 口径。

### 新发现问题（按优先级）

**P1｜nginx 未对 JS/CSS 启用 gzip（首次加载 17~20 秒）**

- 现象：JS 主包 1.24MB 原样传输（带不带 Accept-Encoding 均为 1,242,865 字节，无 Content-Encoding）；HTML 有 gzip（367KB→123KB）。这是 nginx 默认 `gzip_types` 只含 text/html 的典型表现。
- 实测带宽：公网出口仅 ~0.5-0.6Mbps（HTML min 0.157s / 中位 1.1s / max 9.1s；JS 首次加载 6~17s，两次 20s 超时）。
- 影响：校外/手机网络的督导专家首次打开页面极慢；二次访问靠浏览器协商缓存（304）略好。
- 处置（服务器 nginx 一行配置）：`gzip_types text/css application/javascript application/json;`（或构建期预压缩 + `gzip_static on`，体积可再降 ~77% 至 287KB）。改完 `nginx -t && systemctl reload nginx` 即可，无需动应用。

**P2｜哈希静态资源缓存策略过弱**：`/assets/*` 文件名带内容哈希却返回 `Cache-Control: max-age=0`，每次访问都要回源协商。可设 `location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable"; }`，与 P1 同一次配置变更顺带处理。

**P3｜nginx 版本号暴露**：404 页显示 `nginx/1.24.0 (Ubuntu)`，可加 `server_tokens off;`。
