## 三、过程事件（均已处置，如实记录）

**F-4｜esbuild 多入口输出布局陷阱（高危，本地冒烟拦截）**
构建新增迁移脚本入口后，esbuild 按两个入口的公共父目录输出——新服务端代码落到 `dist/_core/index.js`，而容器执行的 `dist/index.js` 是**未被覆盖的旧文件**（esbuild 不清输出目录）。若当时按「先迁移后部署」上线，旧代码遇到哈希口令=**全员锁死**。本地登录冒烟当场拦截。修复：迁移脚本移至 `server/_core/` 使双入口同父目录（输出回落 dist 根），构建脚本固化；后续任何构建布局变化必须先过登录冒烟。

**F-5｜我方误提交：数据 dump 进入公开仓库（已彻底清除）**
本轮 `git add -A` 误将含 101 名老师个人信息（姓名/工号/手机/邮箱）与明文口令的 10-11 数据基线 dump 提交并推送到**公开**仓库（暴露约 1 小时）。处置：`git filter-repo` 从全部历史清除并强推（现历史 1f986de 干净，本地与服务器留档不受影响）；`.gitignore` 增加 dump 规则防再犯。残余风险：① GitHub 对已删除对象的缓存视图可能短期残留，如需彻底可联系 GitHub 支持清除；② 该 dump 中口令均为默认工号，凭据风险已由本轮哈希化+改密建议覆盖；③ 个人信息外泄窗口期短、且文件名不含标识，被检索概率低，但仍建议知悉。**教训：含数据文件永远不进仓库目录**，后续备份导出统一放项目目录外（已将本轮及今后 dump/快照的存放位置改到 `../督导系统备份/`，见第 14 轮起执行）。
